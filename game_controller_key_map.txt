# TankTv 输入映射表（遥控器 / 手柄）

- 适用版本：`1.0.0`（tag `1.0.0`，提交 `671d4f0 Add gamepad support`）
- 相关代码：
  - `app/app/src/main/java/com/zcc/tanktv/GameActivity.java` —— TankTv 的输入改写层
  - `app/app/src/main/java/org/libsdl/app/SDLActivity.java` —— SDL 键码入口（`onNativeKeyDown/Up`）
  - `third_party/SDL/src/video/android/SDL_androidkeyboard.c` —— Android keycode → SDL scancode 表
  - `game/src/engine/sdl/sdl_event_mapper.h` —— SDL 事件 → 游戏 `KeyCode`
  - `game/src/appconfig.h` —— 玩家键位与开火键
- 用途：记录已完成的手柄/遥控器映射，并给出可复制到其他 SDL2 移植项目的实现骨架。

---

## 0. 输入链路

```
手柄按键 / 摇杆轴 / 十字键帽
        │
        ▼
GameActivity.dispatchKeyEvent()        ← TankTv 改写：按键 → 开火
GameActivity.dispatchGenericMotionEvent()  ← TankTv 改写：轴 → 方向键
        │
        ▼
SDLActivity.onNativeKeyDown(Android keycode) / onNativeKeyUp(...)
        │
        ▼
SDL 的 Android keycode → scancode 表
        │
        ▼
SDL_KEYDOWN / SDL_KEYUP（keysym.scancode、keysym.sym）
        │
        ▼
sdl_event_mapper.h：按 keysym.sym 转成游戏 KeyCode
        │
        ▼
菜单 / 选关 / 游戏状态机 / Player
```

关键点：**游戏只读 SDL 键盘事件**。手柄按键如果不拦截，会被 SDL 当成控制器按钮
（`SDLControllerManager.onNativePadDown`）走另一条通道，游戏收不到；所以方向与开火都要在 Java 层改写成键盘键码。

### 1.3 未映射的手柄输入

| 输入 | Android keycode | 当前行为 |
|---|---|---|
| L2 / R2 | 104 / 105 | 未拦截，交给 SDL 控制器通道，游戏不响应 |
| 左/右摇杆按下 | 106 / 107 | 同上 |
| Start / Select / Mode | 108 / 109 / 110 | 同上 |
| 手柄 D-pad 直接上报 `KEYCODE_DPAD_*` 的型号 | 19–22 | 未拦截，走 SDL 控制器通道；方向主要依赖 HAT/摇杆轴 |
| 手柄 OK（`KEYCODE_DPAD_CENTER`） | 23 | 未拦截，SDL 译成 `SELECT`，游戏不识别 |

### 1.4 实现要点

- 方向采用**边沿触发**：只在「未按下 → 按下」「按下 → 未按下」时各发一次
  `onNativeKeyDown/Up`，避免手柄每帧重复发送。状态用位掩码去重：`1=上 2=下 4=左 8=右`。
- 游戏侧 `Player::handleKeyboardEvent` 记录的是**按键状态**（pressed 标志），
  所以必须成对发送 DOWN / UP，只发 DOWN 会导致坦克一直移动。
- 必须在 `dispatchGenericMotionEvent` 末尾调用 `super`，保留 SDL 自己的手柄/摇杆处理。
- 摇杆阈值硬编码为 `0.5`。

### 2.2 开火兜底键（阶段 F）

所以把遥控器上的空闲键统一改写成开火（`KEYCODE_CTRL_RIGHT` → `SDL_SCANCODE_RCTRL`）：

| 节目指南 | `KEYCODE_GUIDE` | 172 |

菜单、播放/暂停、停止、收藏虽然有 scancode，但游戏也不识别。所以必须在 Java 层用原始
Android keycode 拦截，不能放在 SDL 事件过滤器里。

### 2.3 设备差异（换遥控器时必须确认）

TankTv 这台电视的 OK/返回直接是 `ENTER`/`ESCAPE`，所以能对上游戏的 `KEY_RETURN`/`KEY_ESCAPE`。
但很多遥控器会这样上报：

| 遥控器键 | 常见 Android keycode | SDL 会译成 | 游戏 mapper 是否识别 |
|---|---|---|---|
| OK / 确定 | `KEYCODE_DPAD_CENTER` (23) | `SDL_SCANCODE_SELECT` (119) / sym 1073741943 | ❌ 不识别 |
| 返回 | `KEYCODE_BACK` (4) | `SDL_SCANCODE_AC_BACK` (270) / sym 1073742094 | ❌ 不识别 |

遇到这类遥控器，需要在 Java 层做归一化（见 §4.3），否则 OK/返回会失效。

## 4. 可复用实现（复制到其他 SDL2 游戏）

### 4.1 手柄方向（`GameActivity`）

```java
private int mDirPressed = 0;   // 1=上 2=下 4=左 8=右

@Override
public boolean dispatchGenericMotionEvent(MotionEvent event) {
    float hatX = event.getAxisValue(MotionEvent.AXIS_HAT_X);
    float hatY = event.getAxisValue(MotionEvent.AXIS_HAT_Y);
    float stickX = event.getAxisValue(MotionEvent.AXIS_X);
    float stickY = event.getAxisValue(MotionEvent.AXIS_Y);

    float x = 0f, y = 0f;
    if (hatX != 0f || hatY != 0f) {
        x = hatX;
        y = hatY;                       // 十字键优先
    } else {
        if (Math.abs(stickX) > 0.5f) x = stickX;
        if (Math.abs(stickY) > 0.5f) y = stickY;
    }
    applyDirection(x, y);
    return super.dispatchGenericMotionEvent(event);
}

private void applyDirection(float x, float y) {
    updateDir(1, y < -0.5f, KeyEvent.KEYCODE_DPAD_UP);
    updateDir(2, y >  0.5f, KeyEvent.KEYCODE_DPAD_DOWN);
    updateDir(4, x < -0.5f, KeyEvent.KEYCODE_DPAD_LEFT);
    updateDir(8, x >  0.5f, KeyEvent.KEYCODE_DPAD_RIGHT);
}

private void updateDir(int mask, boolean pressed, int keyCode) {
    boolean was = (mDirPressed & mask) != 0;
    if (pressed && !was) {
        SDLActivity.onNativeKeyDown(keyCode);
    } else if (!pressed && was) {
        SDLActivity.onNativeKeyUp(keyCode);
    }
    if (pressed) mDirPressed |= mask;
    else mDirPressed &= ~mask;
}
```

### 4.2 任意键 → 开火

```java
@Override
public boolean dispatchKeyEvent(KeyEvent event) {
    int keyCode = event.getKeyCode();
    if (isFireSourceKey(keyCode)) {
        if (event.getAction() == KeyEvent.ACTION_DOWN) {
            SDLActivity.onNativeKeyDown(KeyEvent.KEYCODE_CTRL_RIGHT);
            return true;
        } else if (event.getAction() == KeyEvent.ACTION_UP) {
            SDLActivity.onNativeKeyUp(KeyEvent.KEYCODE_CTRL_RIGHT);
            return true;
        }
    }
    return super.dispatchKeyEvent(event);
}

private static boolean isFireSourceKey(int keyCode) {
    switch (keyCode) {
        case KeyEvent.KEYCODE_BUTTON_A:
        case KeyEvent.KEYCODE_BUTTON_B:
        case KeyEvent.KEYCODE_BUTTON_C:
        case KeyEvent.KEYCODE_BUTTON_X:
        case KeyEvent.KEYCODE_BUTTON_Y:
        case KeyEvent.KEYCODE_BUTTON_Z:
        case KeyEvent.KEYCODE_BUTTON_L1:
        case KeyEvent.KEYCODE_BUTTON_R1:
        case KeyEvent.KEYCODE_MENU:
        case KeyEvent.KEYCODE_CHANNEL_UP:
        case KeyEvent.KEYCODE_CHANNEL_DOWN:
        case KeyEvent.KEYCODE_PROG_RED:
        case KeyEvent.KEYCODE_PROG_GREEN:
        case KeyEvent.KEYCODE_PROG_YELLOW:
        case KeyEvent.KEYCODE_PROG_BLUE:
        case KeyEvent.KEYCODE_GUIDE:
        case KeyEvent.KEYCODE_INFO:
        case KeyEvent.KEYCODE_SETTINGS:
        case KeyEvent.KEYCODE_MEDIA_PLAY_PAUSE:
        case KeyEvent.KEYCODE_MEDIA_STOP:
        case KeyEvent.KEYCODE_BOOKMARK:
        case KeyEvent.KEYCODE_CAPTIONS:
        case KeyEvent.KEYCODE_DVR:
        case KeyEvent.KEYCODE_TV_CONTENTS_MENU:
        case KeyEvent.KEYCODE_TV_MEDIA_CONTEXT_MENU:
            return true;
        default:
            return false;
    }
}
```

### 4.3 可选：OK / 返回 归一化（TankTv 当前未启用）

```java
// 放在 dispatchKeyEvent 里，开火判断之后
int normalized = keyCode;
if (keyCode == KeyEvent.KEYCODE_DPAD_CENTER) {
    normalized = KeyEvent.KEYCODE_ENTER;   // OK → 回车
} else if (keyCode == KeyEvent.KEYCODE_BACK) {
    normalized = KeyEvent.KEYCODE_ESCAPE;  // 返回 → Esc
}
if (normalized != keyCode) {
    if (event.getAction() == KeyEvent.ACTION_DOWN) {
        SDLActivity.onNativeKeyDown(normalized);
    } else if (event.getAction() == KeyEvent.ACTION_UP) {
        SDLActivity.onNativeKeyUp(normalized);
    }
    return true;
}
```

TankTv 的遥控器直接上报 `ENTER`/`ESCAPE`，所以没有启用这段；换设备时可以加上以兼容
`DPAD_CENTER`/`BACK` 型遥控器。

### 4.4 移植步骤

1. 确认目标游戏的核心键位（方向、开火、确认、返回）对应哪些 `KeyCode` / `sym`。
2. 手柄方向：用 `dispatchGenericMotionEvent` 读 `HAT`/`AXIS`，按 §4.1 合成方向键。
3. 开火：把游戏要求的开火键码填进 §4.2，把空闲键/手柄键改写成该键码。
4. 确认/返回：若游戏只认 `RETURN`/`ESCAPE`，按 §4.3 归一化。
5. 每次改动只在 `ACTION_DOWN && repeatCount == 0` 打一次日志，便于实机核对键值。

## 5. 已知限制与坑

1. **手柄按键必须在 Java 层拦截**：SDL 会把 `KEYCODE_BUTTON_*` 当成控制器按钮
   （`SDLControllerManager.onNativePadDown`），游戏只读键盘，收不到。
2. **SDL 的 Android 键表不等于遥控器实测值**：`DPAD_CENTER → SELECT`、`BACK → AC_BACK`，
   而 `sdl_event_mapper.h` 只识别 `RETURN`/`ESCAPE`。换遥控器时按 §4.3 处理。
3. **B / Y 在本作里也是开火**：提交说明写的是「B=返回、Y=确认仍然有效」，但当前
   `isFireSourceKey()` 同时包含 `BUTTON_B`(97) 和 `BUTTON_Y`(100)，标准手柄上报这两个键时
   会被改写成开火，不会到达 SDL。只有当手柄把 B/Y 上报成 `KEYCODE_BACK`/`KEYCODE_ENTER`
   （部分 TV 模式手柄会这样）时，才表现为返回/确认。要固定语义，需把 B/Y 移出开火列表。
4. **手柄 D-pad 以按键事件上报的型号**：本实现只处理 HAT/摇杆轴。若某手柄的十字键上报
   `KEYCODE_DPAD_*`，这些事件会走 SDL 控制器通道，方向可能无效；可在 `dispatchKeyEvent`
   里把 `SOURCE_GAMEPAD/SOURCE_JOYSTICK` 的 `DPAD_*` 改写后转发到键盘通道。
5. **方向必须成对发送 DOWN/UP**：游戏用按键状态驱动移动，只发 DOWN 会一直走。
6. **按住方向键会产生重复 DOWN**：`updateDir` 的位掩码去重保证每个方向只发一次边沿。
7. **摇杆死区**：阈值固定 `0.5`，廉价手柄可能漂移；可提高到 `0.6` 或按轴单独设死区。
8. **只做了 1P**：2P 开火键是 `KEYCODE_CTRL_LEFT`(113)，2P 移动是 W/S/A/D，未映射到手柄。
